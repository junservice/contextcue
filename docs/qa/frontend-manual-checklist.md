# Frontend 수동 QA 체크리스트

보호자 설정 화면, 가방 챙기기 데모 및 기존 우유·자동문 API 데모를 브라우저에서 검증하기 위한 문서입니다.

**이 문서는 검증 계획입니다. 체크리스트 작성이나 CI 통과가 수동 QA 통과를 의미하지 않습니다.** 아래 결과는 실행 후 기록합니다.

## 1. 실행 정보와 준비사항

| 항목 | 기록 |
|---|---|
| 실행자 | |
| 검증일·시간대 | |
| 브랜치·commit | |
| 브라우저·버전 | |
| 운영체제 | |
| 화면 크기·확대 비율 | |
| 화면 낭독기·버전 | |
| Frontend 주소 | |
| Backend 주소·모드 | |

- Frontend를 실행할 수 있는 팀원의 PC 또는 준비된 검증 환경에서 수행합니다. Node.js가 없는 PC에 설치하도록 요구하는 문서는 아닙니다.
- 보호자 설정과 가방 데모는 backend 없이도 동작해야 합니다.
- API 회귀 검증은 backend를 **DEMO_RULES 모드**로 실행한 환경에서 수행합니다. LIVE_NEBIUS나 실제 AI 호출은 필요하지 않습니다.
- 브라우저 개발자 도구의 Network에서 Fetch/XHR 필터를 선택합니다. 호출 없음 검증 전에는 진행 중인 기존 API 요청이 없는지 확인하고 기록을 지웁니다.
- `DEMO_SCENE`은 합성 장면, `DEMO_RULES`는 로컬 규칙을 뜻합니다. 실제 카메라 감지·행동 성공·라이브 추론으로 설명하지 않습니다.
- 실제 개인정보나 장애 기록을 입력하지 않습니다. 실패 증빙에도 비밀키·개인정보를 포함하지 않습니다.
- 모든 테스트 결과의 초기값은 ‘미실행’입니다. 실행 후 기록란을 ‘통과 / 실패 / 재현 불가’ 중 하나로 변경합니다. 아직 실행하지 못한 항목은 ‘미실행’을 유지하고, 미실행·재현 불가 사유는 아래 이슈 기록에 남깁니다. 통과로 처리하지 않습니다.

### 합성 초기 프로필

| 사용자 | 팔 뻗기 | 물건 잡기 | 버튼 정확히 누르기 | 선호 안내 방식 |
|---|---|---|---|---|
| A | 가능 | 가능 | 미확인 | 대상 강조 표시 |
| B | 어려움 | 미확인 | 어려움 | 화살표 안내, 음성 안내 |

초기값은 기능 시연을 위한 임의 데이터이며 실제 사용자의 능력이나 평가 결과가 아닙니다.

## 3. 가방 챙기기 데모

| 테스트 ID | 사전 조건 | 실행 순서 | 예상 결과 | 기록 |
|---|---|---|---|---|
| T-01 단계·Next | A 초기 프로필, 처음부터 시작 | 다음 네 번 선택 | 가방 찾기 → 물병 찾기 → 물병 넣기 → 준비물 확인 → 완료. 입력당 한 단계 이동 | 미실행 |
| T-02 도움 0~4 | 첫 단계, 도움 0 | 도움 더 보기 네 번 선택 | 1 → 2 → 3 → 4. 4에서 보호자 확인 상태 전환 | 미실행 |
| T-03 도움 상한 | 도움 4 | 도움 더 보기 재조작 시도 | 비활성 상태이며 4 초과하지 않음 | 미실행 |
| T-04 Pause·Continue | 진행 중, 도움 2 | 잠시 멈춤 → 다음·도움 더 보기 시도 → 계속하기 | 정지 중 진행 불가, 시각 안내 숨김. 같은 단계·도움 2로 재개 | 미실행 |
| T-05 Stop | 진행 중 | 작업 종료 → 진행 버튼 조작 시도 | 종료 문구, 진행 차단. 완료로 표시하지 않음 | 미실행 |
| T-06 Ask for Help | 진행 중 | 보호자 도움 요청 | 단계 유지, 도움 4, 보호자 확인 상태. 실제 알림 전송 주장 없음 | 미실행 |
| T-07 정지 중 도움 요청 | paused 상태 | 보호자 도움 요청 | 같은 단계에서 도움 4·보호자 확인 상태 전환 | 미실행 |
| T-08 확인 전 차단 | help_requested 상태 | 다음·도움 더 보기·잠시 멈춤·계속하기 조작 시도 | 모두 비활성 상태이고 단계 유지 | 미실행 |
| T-09 보호자 확인 | 첫 단계에서 도움 요청 | 보호자 확인 후 계속 | 물병 찾기로 이동, 도움 0. 프로필 유지 | 미실행 |
| T-10 다음 단계 재확인 | B, 물병 찾기에서 도움 요청 | 보호자 확인 후 계속 | 물병 넣기로 이동하되 능력 조건에 따라 도움 4·도움 요청 상태 | 미실행 |
| T-11 Restart | active·paused·help_requested·stopped·completed 각각 준비 | 각 상태에서 처음부터 시작 | 사용자·프로필 유지, 가방 찾기·도움 0·active 복귀 | 미실행 |
| T-12 완료와 종료 | A 정상 진행 가능 | 완료까지 진행한 경우와 중간 종료한 경우 비교 | completed는 5/5 및 실제 완료 미확인 안내. stopped는 중단 단계와 종료 문구. 양쪽 추가 진행 차단 | 미실행 |
| T-13 수동 진행 표현 | 데모 진행 중 | 각 단계에서 다음 선택 | 성공 관찰 기록이나 물병 이동 그림 생성 없음. 고정 장면·수동 진행 설명 유지 | 미실행 |
| T-14 초기화 | 중간 단계 | 같은 사용자 재선택 → 다른 사용자 선택 → 다시 진행 후 능력 변경 | 같은 사용자 선택은 유지. 다른 사용자·실제 설정 변경은 첫 단계 초기화 및 이유 표시 | 미실행 |
| T-15 화면 전환 | 가방 데모 중간 단계 | 기존 API 화면 이동 → 가방 화면 복귀 | 작업 상태 유지, 자동 진행 없음 | 미실행 |
| T-16 네트워크 분리 | 기존 요청 없음, Network 기록 삭제 | 가방 데모 모든 조작 수행 | API·AI 요청 없음. DEMO_SCENE·DEMO_RULES 표시 | 미실행 |
| T-17 같은 능력값 | 중간 단계 | 현재와 같은 능력값 재선택 | 작업 단계·도움 수준 유지 | 미실행 |
| T-18 안내 변경 초기화 | 중간 단계 | 안내 방식 선택 또는 해제 | 프로필 변경 유지, 작업은 가방 찾기·도움 0·active로 초기화 | 미실행 |

Next와 보호자 확인은 수동 진행 입력입니다. 실제 행동 완료를 시스템이 관찰했다는 뜻이 아닙니다.

Backend를 DEMO_RULES로 실행한 환경에서 수행합니다. LIVE_NEBIUS 호출을 검증하는 항목이 아닙니다.

- 이전 요청 무효화는 응답 표시 차단입니다. 이미 시작한 서버 처리를 취소한다는 의미는 아닙니다.

## 7. 데모 시연 순서

1. 새로고침 후 합성 사용자·페이지 내 임시 설정임을 설명합니다.
2. A/B를 전환하고 사용자별 설정 독립성을 보여줍니다.
3. 안내 방식을 복수 선택했다가 모두 해제해 미설정·텍스트 안내를 보여줍니다.
4. A의 안내 선호를 대상 강조 표시로 설정하고 도움 0~3, Pause·Continue를 시연합니다.
5. Next로 완료까지 진행하고 실제 행동 성공 판정이 아님을 설명합니다.
6. B로 전환해 물병 넣기의 도움 필요 분기를 보여줍니다.
7. 팔 뻗기를 가능으로 바꾸고 잡기를 미확인으로 유지해 미확인 문구의 차이를 보여줍니다.
8. 보호자 확인 후 계속, Stop, Restart를 시연합니다.
9. Network에서 설정·가방 조작으로 API 요청이 발생하지 않았음을 확인합니다.
10. 준비된 DEMO_RULES backend로 우유·자동문 기능을 확인합니다. 사용자 A의 잡기·버튼 능력을 각 시연 조건에 맞게 설정합니다.
