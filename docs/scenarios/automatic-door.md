# 가상 시나리오: 버튼식 자동문 열기

> 증거 구분: `DEMO_SCENE` — 가상의 사용자와 장면을 바탕으로 작성한 시나리오입니다.
> 이 문서는 기대하는 동작을 설명합니다. 구현 완료, 테스트 통과 또는 `LIVE_NEBIUS` 실행을 의미하지 않습니다.

## 1. 입력 정보

프로그램이 전달받는 정보입니다.

| 항목 | 내용 |
|---|---|
| 상황 이름 | 버튼식 자동문 열기 |
| 사용자 능력 | 팔을 뻗을 수 있음. 버튼을 찾아 정확히 누를 수 있는지는 아직 확인되지 않음 |
| 주변 상황 | 사용자 앞에 버튼식 자동문이 있고, 문 옆에 열림 버튼이 관찰됨 |
| 받은 지시 | “문을 열고 들어가세요.” |
| 추가로 확인할 정보 | 버튼의 실제 위치, 사용자가 닿을 수 있는 높이인지, 누르는 동작이 가능한지 |

팔을 뻗을 수 있다는 사실만으로 버튼을 누를 수 있다고 판단하지 않습니다. 누르기 안내 전에 수행 가능성을 확인합니다.

## 2. 기대 결과

사용자가 가능한 범위에서 직접 버튼을 찾아 시도하도록 돕습니다. 도움이 필요하면 한 번에 안내 하나씩 제공합니다.

버튼 강조 표시와 화살표는 검증된 장면 관찰에 포함된 버튼 위치만 사용합니다. 언어 모델은 관찰된 물체 ID만 선택할 수 있으며, 버튼 위치나 좌표를 만들어 내면 안 됩니다. 버튼 위치가 불확실하면 먼저 확인을 요청합니다.

## 3. Least-to-Most 단계

Least-to-Most는 가장 적은 도움부터 시작해서 필요한 만큼만 도움을 늘리는 방식입니다. 아래 단계는 이 시나리오에서 기대하는 흐름이며, 구현된 기능을 뜻하지 않습니다.

| 단계 | 프로그램의 반응 | 다음 단계로 넘어가는 조건 |
|---|---|---|
| 1. 스스로 찾기 | 추가 표시나 음성 없이 버튼을 찾을 시간을 제공 | 사용자가 도움을 요청하거나, 합의한 대기 후에도 찾기 어렵다고 확인됨 |
| 2. 시각적 강조 | 관찰된 열림 버튼 주변을 눈에 잘 띄게 표시 | 강조만으로 찾기 어렵다고 확인됨 |
| 3. 화살표와 음성 | 버튼을 가리키는 화살표와 “열림 버튼은 여기 있어요.”라는 짧은 음성 제공 | 위치를 알아도 누르기 어렵거나 추가 도움이 필요함 |
| 4. 도움·대안 제안 | “보호자에게 도움을 요청할까요?”처럼 짧게 제안 | 사용자의 선택에 따라 도움 요청 또는 중단 |

각 단계에서 목적을 달성하면 도움을 더 늘리지 않습니다. 응답이 없다는 이유만으로 실패로 단정하지 않고, 더 시간이 필요한지 확인합니다. 대기 시간은 이 문서에서 정하지 않으며 사용자에게 맞게 합의해야 합니다.

버튼을 찾는 동안 누를 수 있는 능력을 가정하지 않습니다. 신체적 어려움, 위험 또는 거부가 확인되면 순서대로 모든 단계를 반복하지 않고 즉시 도움 요청이나 중단으로 전환합니다.

## 4. 신체적으로 수행할 수 없을 때의 대응

버튼이 너무 높거나, 팔을 뻗어도 정확히 누르기 어렵다면 어느 단계에서든 누르기 안내를 멈추고 도움 방식으로 전환합니다.

- “버튼을 누르세요”를 반복하지 않습니다.
- 누르는 동작이 가능한지 아직 모르면 확인을 요청합니다.
- 보호자나 현장 직원의 도움을 제안합니다.
- 다른 출입 방법은 실제로 이용 가능한지 확인한 뒤 제안합니다.
- 사용자가 거부하거나 멈추기를 원하면 중단합니다.

버튼을 찾는 어려움과 버튼을 누르는 어려움을 구분합니다. 위치를 더 크게 보여줘도 신체적인 어려움은 해결되지 않을 수 있습니다.

## 5. 성공 여부를 기록할 항목

실제 개인 식별 정보나 장애 기록 대신 가상의 시나리오와 관찰 결과만 기록합니다.

| 기록 항목 | 기록 예시 |
|---|---|
| 버튼을 찾았는가 | 찾음 / 찾지 못함 / 확인 불가 |
| 어떤 도움이 필요했는가 | 도움 없음 / 시각적 강조 / 화살표와 음성 / 사람의 도움 |
| 버튼에 닿을 수 있었는가 | 가능 / 불가능 / 확인되지 않음 |
| 버튼을 눌렀는가 | 관찰됨 / 관찰되지 않음 / 확인 불가 |
| 문이 열렸는가 | 관찰됨 / 열리지 않음 / 확인 불가 |
| 안으로 들어갔는가 | 관찰됨 / 들어가지 않음 / 확인 불가 |
| 중단하거나 도움을 요청한 이유 | 버튼이 높음, 누르기 어려움, 사용자 요청 등 |

버튼 누르기, 문 열림, 들어가기는 각각 따로 확인합니다. 버튼을 눌렀다는 사실만으로 들어가기까지 성공했다고 기록하지 않습니다. 사람의 도움으로 완료했다면 그 사실도 함께 기록합니다. 관찰되지 않은 행동을 완료했다고 단정하지 않습니다.
